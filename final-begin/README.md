# QOJ 斗地主 final-v2

从用户提供的 **final-v1** 修改。三个 Python 文件：在线客户端、离线训练、本地人机对战；共享规则和模型放在 `client/qoj_cli.py`。只有这一份 README，不附测试目录。

**本版更换为自行定义的 546,785 参数模型，随包权重是随机初始化，尚未训练。** 不需要下载 DouZero / AlphaDou，也不使用它们的预训练权重。模型输入包括本局完整公开事件序列和公开底牌；没有“最近 15 手”的截断。

## 1. Windows 11：安装、训练、停止、玩

解压，进入包含 `train.py`、`local.py` 的 `final-v2` 文件夹，在该目录打开 PowerShell 或 Windows Terminal。

推荐 **64 位 Python 3.12**。Surface Snapdragon X Elite 推荐使用原生 **ARM64 Python 3.12**；Intel / AMD 电脑用 x64 Python。训练和推理都用 CPU，不使用 Adreno GPU 或 Hexagon NPU，不需要 g++、Node、CUDA、ONNX 或自行编译 PyTorch。

先安装依赖：

```powershell
python -m pip install --upgrade pip
python -m pip install -r client/requirements.txt
```

开始训练，默认持续运行：

```powershell
python train.py
```

**想玩时，在训练窗口按一次 Ctrl+C，等待出现“训练已停止，最新模型已保存”。** 然后运行其中一条：

```powershell
python local.py
```

```powershell
python client/qoj_cli.py
```

两个客户端都默认读取 **`client/models/current.pt`**，不需要导出、转换或手动移动模型。以后再次运行 `python train.py`，自动恢复模型、优化器、回放和随机数状态。

安装完成后，`train.py` 和 `local.py` 完全离线。只有安装依赖、安装浏览器组件及连接 QOJ 需要网络。

在线连接如果需要随包浏览器，另运行一次：

```powershell
python -m playwright install chromium
```

这是浏览器组件安装，不能用 `pip install chromium` 替代。Windows 客户端也会尝试现有 Edge / Chrome。训练和本地对战不需要安装浏览器组件。

### 可选：虚拟环境

不需要修改 PowerShell 执行策略，直接调用环境中的 Python：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r client/requirements.txt
.\.venv\Scripts\python.exe train.py
```

之后运行客户端时，也使用 `.\.venv\Scripts\python.exe local.py` 或 `.\.venv\Scripts\python.exe client/qoj_cli.py`。

## 3. 训练的具体行为

三名玩家使用当前同一个模型，从各自视角决策；每次随机洗牌、随机选先叫者。训练程序只把行动者自己的手牌和公开信息交给网络。

采用 Monte Carlo 自博弈：完整一局结束后，将每次行动对应玩家的最终积分除以固定的 6，作为该行动的估值目标。地主和农民都使用同一个缩放比例，所以叫分阶段也会考虑成为地主后的双倍盈亏。模型学习的是**期望积分**，不是单纯胜率；炸弹、王炸和春天增加的输赢分数会进入训练目标。

每局默认更新四次，每批 64 条经验。叫分、地主、两个农民位置分成四个回放类别，批次尽量均衡采样。默认每类保留最近 1,024 条，共最多 4,096 条。**回放条数限制与历史长度不同：每条经验内部依然保留该时刻的全部公开历史，不截断。** 训练和回放均使用 float32。

随机探索率从 20% 随累计 200,000 次决策线性降至 5%。推理时没有随机探索，选择模型估值最高的合法行动。这里没有额外的强规则教练、搜索引擎或预训练老师。

### 保存和停止

- 默认每 **60 秒** 保存一次，也在正常结束和 Ctrl+C 后保存。间隔在动作或更新之间检查，可能稍晚于设定时刻。
- `client/models/current.pt` 只含模型结构标识、CPU 权重和统计信息，约 **2.1 MiB**，供两个客户端读取。
- 根目录 `training.pt` 还包含优化器和经验回放，体积随回放增长，通常明显大于客户端模型。
- 保存使用临时文件和原子替换，正常读取不会拿到半个文件。先写续训文件，再发布客户端模型；两步间断电时，再启动训练可重新发布较新的续训权重。
- Ctrl+C 只请求停止，程序会完成当前计算，然后保存。中断时未打完那一局的样本丢弃，续训从新发的一局开始。
- **任务管理器强制结束、直接关机、关闭窗口，不能保证保存内存里最后的更新。** 此时客户端读取上一次成功保存的版本；不要把强制结束当作 Ctrl+C。
- 开始训练时会检查同一模型是否已有训练进程，避免并发覆盖。锁由系统随进程退出释放，不需要手动删除锁文件。
- 本地对战和在线对战都不训练、不修改模型。想继续学习，关闭对战后再运行训练命令。

只保留客户端模型也可以继续训练，但会重新建立优化器和回放。保留配套 `training.pt` 才是完整续训。如果两份文件来自不同训练或续训文件比客户端模型更旧，会报错，避免静默退回旧权重。

### 常用训练命令

| 命令 | 作用 |
|---|---|
| `python train.py` | 默认 4 个 CPU 线程，无限训练；Ctrl+C 保存退出 |
| `python train.py --seconds 600` | 本次训练约 10 分钟后保存退出，用于测本机速度 |
| `python train.py --seconds 86400` | 本次训练约一天后保存退出；电脑必须保持唤醒 |
| `python train.py --games 1000` | 本次再完成 1,000 局后保存退出，不是累计到 1,000 局 |
| `python train.py --threads 2` | 用 2 个 CPU 线程，减少发热和占用；可与 4 线程比较速度 |
| `python train.py --save-interval 600` | 改为每 10 分钟保存；Ctrl+C 仍立即请求最终保存 |
| `python train.py --batch 32 --buffer 512` | 减小批量和回放，降低内存需求 |
| `python train.py --fresh` | 使用当前模型权重，重建优化器和回放；不会恢复成随机模型 |
| `python train.py --help` | 显示全部参数 |

这些参数可以组合。默认内存会随回放填满而增长，建议留出至少约 2 GB 空闲内存；实际占用以任务管理器为准。训练时接电、保持通风，并关闭自动睡眠。GPU/NPU 占用低是正常现象。

控制台显示累计局数、决策数、更新数、当前会话决策/s、均方损失、探索率、近期地主胜率。**损失下降或地主胜率变化，不等于真人对战水平提高。** 三方都在变化，自博弈胜率尤其不能直接用来评强度。

新架构从零开始，未承诺训练几天能达到某个人类水平。先运行 10 分钟取得本机决策速度 `r`；连续一天的粗略样本量是 `r × 86400`，实际还受对局长度、散热和保存开销影响。运行一段时间后，用 `local.py` 实际对战判断，不要把训练天数当成强度保证。

### 重新从随机参数开始 / 回退

完全从头开始：停止程序，在新目录重新解压本包并训练。这样保留已有成果，不需要任何重置命令。

回退自己的备份：停止程序后恢复配套 `training.pt` 和 `client/models/current.pt`。如果只有旧的客户端模型，替换后用 `python train.py --fresh` 重建续训状态。

**final-v1 模型不能用于 final-v2。** 不要把旧 `current.pt`、`live.pt`、`latest.pt` 或旧训练目录复制进来。本版删除了旧权重导入、旧微调学习率和 `live.pt` 选取逻辑。

### 模拟器采用的规则

54 张牌，每家 17 张、留 3 张底牌，随机选先叫者，依次各叫一次；不叫或叫高于当前的 1 / 2 / 3 分，叫 3 立即结束叫分。三家都不叫就重新洗牌，并重新随机先叫者。沿用 final-v1 的解释：**连续流局 3 次后，第 4 次发牌的最后一家在此前两家都不叫时必须叫分。** 叫分结束才确定地主、公开并发给地主底牌；地主先出。

大小为 3–A、2、小王、大王。不分花色；支持单张、对子、三张、三带一、三带一对；至少五张顺子、至少三对连对、至少两组三张飞机及等组数单牌 / 对子翅膀；四带二、四带两对；炸弹和王炸。顺子、连对和飞机主体不能带 2 或王。带牌不能与主体同点，也不能包含炸弹或王炸。四带二的两张单牌可以是一对。跟牌要求同型同长度且更大，炸弹和王炸按原规则覆盖；两家都过则上一出牌者自由出牌。

底分为地主叫分，倍率从 1 开始，每个炸弹或王炸 **加 1**。地主胜且农民从未出牌为春天；农民胜且地主只出过一手为反春；任一种再加 1。地主胜得 `2 × 底分 × 倍率`，各农民分别输 `底分 × 倍率`；农民胜则反之。不是传统的每个炸弹乘 2。

## 4. 模型究竟看到了什么

只谈决策所需的当前一局信息。在线比赛仍按逐局期望积分决策，不用九局排名制定追分策略，也不跨局学习某个人的习惯。

| 信息 | 编码方式 |
|---|---|
| 自己当前手牌 | 15 种点数的张数，含 2 和双王 |
| 自己最初的 17 张牌 | 由当前手牌、自己的已出牌、地主底牌还原 |
| 未出现牌的总集合 | 整副牌减自己的当前手牌和本次发牌所有已出牌；不猜测分给谁 |
| 公开三张底牌 | 单独编码；同时标明地主相对位置 |
| 尚未打出的公开底牌 | 按公开真实卡片 ID 扣除已经打出的底牌，再编码点数；农民也能利用已知归属 |
| 三人的位置、地主位置、当前行动者、先叫者、最近出牌者 | 相对自己编码，分清上下家及未知位置 |
| 三人剩余张数、各自累计已出牌、出过几手牌 | 单独编码 |
| 各自最近一手非过牌、最近一次动作类型 | 单独编码；完整时序另在历史中保留 |
| 各家叫过几分、未叫 / 不叫的区别 | 从本次发牌公开叫分日志恢复，兼容服务器 `bid=null` |
| 当前待跟的牌和选定牌型 | 具体点数、牌型、主点、长度；服务器 `last` 不带牌时从日志恢复 |
| 底分、当前倍率、炸弹数、流局次数 | 单独编码；已流局次数也从完整日志恢复，不因界面清零丢失 |
| 自由出牌、强制叫分、已叫人数、连续过牌次数 | 单独编码 |
| 春天 / 反春相关状态 | 三人出牌手数、农民是否还都没出牌、地主是否只出过至多一手、地主是否已开始出牌 |
| 完整公开历史 | 从本局最开始到现在的每次叫分、流局、确定地主及底牌、出牌、过牌；严格按顺序，无最近 N 手窗口 |
| 历史每一手的含义 | 行动者、牌张、选择的牌型及主点和长度、叫分值、当时累计公开状态；保留此前流局的叫分历史 |
| 每个候选行动 | 叫分 / 出牌 / 过、候选牌、牌型、出后自己剩余牌、是否一手走完、是否炸弹 |

模型不会获得对手未公开手牌、未公开底牌、发牌随机种子、公平性完整牌堆、未来动作、Cookie 或聊天。花色不输入网络；聊天、操作时间、服务器托管开关、账户 Rating 和跨局分表不作为牌力特征。

**“完整输入”不等于“学会了完美记忆或推理”。** 输入编码保留了所有上述公开策略事件，但网络是否学会利用很早的过牌、叫分和配合关系，仍依赖训练。它不能从公开信息唯一还原对手全部手牌。

### 网络结构

自行定义的 `QOJ-FullHistoryQ`，共 **546,785** 个参数，全部可训练：

1. 当前局面：264 维 → 两层 256 维全连接。
2. 每个公开事件：68 维 → 96 维 → 单层 128 维 GRU，读取完整变长历史。
3. 当前局面作为查询，对**全部有效历史位置**做注意力汇总，并拼接 GRU 最后一个有效位置，再融合为 256 维局面特征。
4. 合法候选行动：57 维 → 两层 128 维全连接。
5. 局面与行动特征拼接，经 256、128 维全连接输出一个分值；推理时乘 6 显示为预计本局积分。

叫分和三个出牌位置共享网络，通过阶段和相对角色区分。每次决策从完整历史重新计算；训练批次按最长历史补零，掩码排除补零位置，不裁剪历史。候选行动分批估值，但局面与历史只编码一次。

随机初始化种子为 `20261004`；交付模型 `frames=0`、`games=0`、`updates=0`。训练验收使用另存的临时模型，不混入交付参数。默认权重与依赖采用 CPU 格式，Windows 与 Linux 无需转换模型。

未训练时可能乱叫分、偏爱过牌，这是随机网络的表现。自由出牌仍不允许过，非法行动不会提交；接口错误或加载错误会明确报错，不会自动变成“过”。

## 5. 本地对战

```powershell
python local.py
```

启动立即随机发牌、随机先叫，一名人类对两名当前模型。沿用 QOJ 风格的全屏动态界面，删除聊天区和联网功能；两个 bot 的手牌不显示。人类可能成为地主或农民，农民时其中一个 bot 是队友。

| 输入 | 功能 |
|---|---|
| `0` / `-`、`1` / `2` / `3` | 叫分阶段不叫或叫分，必须超过当前最高分 |
| `3334`、`789XJQKA` 等 | 出牌；出牌阶段的 `2` / `3` 是实际的牌 |
| `-` | 跟牌阶段过；自由出牌时不可过 |
| `/ai` | 轮到自己时给出本地模型建议，不自动提交 |
| `/bot on` / `/bot off` | 开启 / 关闭自己这家的本地模型托管 |
| `/sort` | 切换手牌升序 / 降序 |
| `/play 牌面` | 明确输入牌面 |
| `/choose 编号` 或 `牌面#编号` | 多种牌型解释时选择一种 |
| `/help` | 简短操作说明 |
| `/quit` / Ctrl+C | 提前结束本地对战 |
| F2 / Esc | 日志向前查看 / 回到最新 |

一局结束后自动退出全屏，在终端打印完整公开日志、你的开局手牌及结算；提前退出也打印已发生的日志。纯本地模式不接受聊天、服务器 `/hint`、服务器 `/auto`、大厅或比赛命令。

可选：`python local.py --seat 2` 指定自己座位；`--seed 123` 固定发牌随机种子；`--model 路径` 使用另一个 final-v2 模型。默认始终读取 `client/models/current.pt`。

## 6. QOJ 在线客户端

```powershell
python client/qoj_cli.py
```

输入 `__Host-UOJSESSID` 的值，也接受 `__Host-UOJSESSID=值` 或包含该字段的完整 Cookie；只提取该字段。输入不回显，程序不把 Cookie、CSRF token 或浏览器会话保存到磁盘。

推荐 Windows Terminal / UTF-8 Linux 终端，约 100 列 × 30 行。程序不依赖 curses。窗口小会缩短可见日志；轮询重绘保留正在输入的内容。在线原功能保留：单局、九局记分比赛、聊天、规则提示、服务器托管、公平性核验、终局开局手牌查看和断线恢复。

### 牌面输入

`X`、`T`、`10` 都表示 10；`S` / `小王`、`D` / `大王`；`SD` 是王炸。支持大小写、空格和逗号。程序从自己的真实手牌中选择对应卡片 ID，不假定花色。

纯牌面字符串会被作为出牌尝试；缺牌、不合法、管不上或未轮到时显示错误。其他普通文本作为聊天；如聊天内容刚好是牌面字符，请用 `/say 333`。聊天最多 60 个 UTF-16 字符。

多解牌保留 final-v1 的明确选择机制。人工先查看选项，再 `/choose 2` 或输入 `牌面#2`；模型把不同合法解释作为不同候选行动。旧选择在牌局变化后作废。

### 大厅与对局命令

| 输入 | 功能 |
|---|---|
| 大厅 `1` / `2` | 单局匹配 / 九局记分比赛；有进行中的对局则恢复 |
| `/cancel` | 取消尚未开始的匹配 |
| `/refresh` | 刷新资料、token 和状态 |
| `/ai` | 当前轮到自己时，本地模型叫分 / 出牌建议；显示估值，不是胜率 |
| `/bot on` / `/bot off` | 当前电脑的本地模型托管开关；关闭 CLI 后不会继续运行 |
| `/hint` | 保留原客户端的规则出牌提示，没有模型估值 |
| `/auto on` / `/auto off` | QOJ 服务器托管；与 `/bot` 是两种不同机制 |
| `/play 牌面` / `/choose 编号` | 明确出牌 / 选择牌型 |
| `/say 内容` / 普通文本 | 聊天 |
| `/mute` / `/sort` | 聊天屏蔽开关 / 手牌排序 |
| `/log` / `/chat` | 全部日志 / 聊天 |
| `/fair` | 发牌承诺；终局核验 SHA-256、牌序和随机盐 |
| `/initial` | 终局查看最后一次发牌的三人开局牌及底牌 |
| `/score` / `/scores` | 九局比赛分表，终局包括名次与 Rating |
| `/again` | 单局结束后再匹配单局；整场比赛结束后再匹配比赛 |
| `/home` | 单局或整场比赛结束后回大厅 |
| `/browser` | 打开 / 重试浏览器连接 |
| `/help` / `/close` / Esc | 查看说明 / 关闭详情 |
| F2 / F3、PgUp / PgDn | 翻看日志 / 聊天；滚动已打开的详情 |
| `/quit` / Ctrl+C | 退出客户端；排队时尝试取消排队 |

本地托管会取消自己已开启的服务器托管，并在轮询观察到服务器重新托管时再尝试取消；开启 `/auto on` 会关闭本地托管。模型错误或真正的计算超时会显示原因并暂停，不会用默认“过”伪装成模型决策。旧局面回复不会提交到新局面。

九局比赛由服务器创建和结算。局间显示分表，约五秒后按服务器给出的下一局跳转；不会自行创建下一局或第十局。跨局清空旧输入和牌型选择。整场未结束时不能用 `/again`、`/home` 提前重开。退出 CLI 不会终止服务器对局；重开程序可恢复。

### Cloudflare 和浏览器

默认 `--transport auto` 先用 curl-cffi；遇到验证时尝试真实浏览器。需要时在弹窗内手工验证，并保持窗口打开；后续请求通过同一浏览器页面的同源 fetch 发送。保留阻止网页斗地主业务脚本运行的逻辑，避免 CLI 与网页双重轮询。

```powershell
python client/qoj_cli.py --transport browser --browser msedge
python client/qoj_cli.py --transport browser --browser chromium
python client/qoj_cli.py --transport http
python client/qoj_cli.py --demo
```

`http` 不自动打开浏览器，适用于无需交互验证的纯终端环境；`--demo` 是无需登录的静态界面演示，不发送动作。Cloudflare 是否接受连接由站点决定，不承诺绕过验证。Linux 若需要手动浏览器验证，需要图形桌面；纯 SSH 不能点击弹窗。Linux 浏览器缺系统库时，可按 Playwright 提示执行 `python3 -m playwright install --with-deps chromium`，可能需要管理员权限。

出牌、叫分、聊天等写请求若发生超时或验证中断，不自动重发，应先确认随后同步的状态。没有新增任何远程训练或数据上传功能。

## 7. Linux 使用与兼容范围

`qoj_cli.py` 和 `local.py` 使用同一份跨平台源码及 CPU 模型。Linux 推荐 Ubuntu 22.04+ / Debian 12+ 的 x86-64 或 aarch64，64 位 Python 3.12。示例：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r client/requirements.txt
.venv/bin/python local.py
```

联机时把最后一条换成 `.venv/bin/python client/qoj_cli.py`。如果需要浏览器，运行 `.venv/bin/python -m playwright install chromium`。

`train.py` 按 Windows 11 使用场景提供，未依赖 Unix 专属 API；其中 Linux 分支用于开发验收，不要求用户在 Linux 训练。Windows ARM64、Windows x64 与 Linux 之间复制 `current.pt` 后无需模型转换。

唯一依赖清单：

| pip 库 | 用途 |
|---|---|
| `torch==2.10.0+cpu` | CPU 模型、训练、保存；使用 PyTorch CPU wheel 源 |
| `numpy>=1.26,<3` | 公开信息编码 |
| `prompt_toolkit>=3.0.48,<4` | 两个客户端的动态终端界面 |
| `beautifulsoup4>=4.12,<5` | QOJ HTML 解析 |
| `curl_cffi>=0.16.3,<0.17` | 在线 HTTP/TLS |
| `playwright>=1.55,<2` | 在线浏览器验证回退 |

推荐直接安装整个清单。只训练、不运行界面时也可仅安装 PyTorch CPU 和 NumPy；本地对战再加 prompt_toolkit。依赖安装需要网络，安装好后离线训练无需 GitHub 下载或任何外部资源。

若 pip 提示没有匹配的 torch wheel，先确认使用 64 位标准 CPython 3.12、升级 pip，并使用本包 requirements 中的 CPU 源；不要把不同架构 Python 的环境混在一起。官方 CPU 索引已提供该版本的 Windows ARM64、Windows x64 及 Linux wheel，见文末链接。

### 决策时限与验证范围

模型推理由独立进程执行，常驻加载；正常模型计算预算为 4 秒，控制超时并丢弃过期结果。冷启动加载会显示等待。联网时间、首次启动时间、系统长时间卡顿不属于纯模型计算时间，不能承诺所有电脑的端到端响应一定小于 5 秒。

开发环境是 Linux x86-64 CPU。完成了真实公开牌局的逐步回放及特征核对、真实模型联机接口模拟、本地全屏整局、完整历史与补零掩码检查、真实梯度更新、定时保存、Ctrl+C 最终保存、模型一致性与完整续训检查。没有用户 Cookie，未进行真实账号联机操作；未在实体 Surface / Windows 11 上实测。

该环境两线程下，随机初始模型在 354 次整局决策及 102 手额外候选牌压力样本中，含动作枚举的单次最大约 0.010 秒；这些数字不是 Surface 的性能保证。训练时的本机速度应以控制台为准。

## 8. 模型文件、打包与来源

`current.pt` 是 PyTorch 字典，包含 `schema=2`、架构标识、CPU `state_dict` 和训练统计。运行时只需它及本包代码，不需要优化器文件。新的 `Agent` 和两个客户端共用同一个 `prepare()`，避免训练 / 本地 / 联机使用不同的特征顺序。

python client/qoj_cli.py --package
